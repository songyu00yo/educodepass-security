# EduCodePass 客户端安全评估

本仓库记录对 EduCodePass macOS 客户端的安全评估。EduCodePass 用于东软信息学院“码途”编程练习。

当前评估版本为 **1.3.2**；1.3.0 的评估结论保留在同一份报告中作为对照基线。

[安全发现与验证边界](SECURITY-REPORT.md) · [技术细节与验证代码](SECURITY-REPORT-FULL.md) · [许可证](LICENSE)

## 版本变化要点

1.3.2 相对 1.3.0 有四处实质变化，其中一处是防护退化：

| 变化 | 方向 |
| --- | --- |
| `sign_request` 从 ACL 拒绝变为放行，且实测可成功签出 ECDSA P-256 签名 | **退化**（V-17） |
| 新增已加载镜像枚举检测，判据为镜像路径前缀 | 增强，但可绕过（V-21） |
| 新增截屏产物内容自检（识别窗口被隐藏） | 增强（V-22） |
| 进程黑名单本地词表由约 180 项扩至 216 项，集中新增 AI 编程工具与通讯软件 | 增强 |
| 设备指纹新增 `diskutil` 卷 UUID | 增强 |

官方更新清单对该版本的自述为：`1.3.2：补齐设备多源指纹（卷 UUID + IOPlatformUUID），与 Windows 1.3.3 对齐`。

## 主要发现

设备私钥读取仍是评级最高的当前发现。1.3.2 中该项的实现方式已确认：密钥由 `/usr/bin/security` 命令行工具管理，种子取自 `/dev/urandom`，未使用 Security.framework、未配置访问控制、未使用 Secure Enclave。

1.3.2 新增的问题中，影响最大的是签名命令的权限变化。原报告记录该命令对页面脚本返回 ACL 拒绝；1.3.2 中同一路径可达参数校验阶段，补齐参数后返回结构合法的设备签名。服务端是否另有独立校验未经测试。

其余发现涉及客户端修改、本地检测、配置下发与行为指标上报。各项测试条件、观察结果与局限见[安全报告](SECURITY-REPORT.md)。

## 评估范围

报告声明评估在授权范围内完成，验证限于本地测试环境，未对生产服务端发起攻击。动态实测与静态推断分别标注；本地检测结果不代表服务端的最终判定。

对敏感 IPC 命令的探测一律只传空参数、止步于参数校验阶段；带副作用的命令（设备标识写入、截图、更新安装、关闭窗口）未调用。

## 负向结论

评估中排除的几项，供后续复核参考：

- 本地篡改 `config.json` 清空进程黑名单**无效**：重启后会被服务端重新下发覆盖。
- 客户端启动与登录阶段**不调用** `ps`：探针调用记录为空，客户端正常驻留五分钟以上。
- 前端包内**未发现**硬编码密钥、Token 或内部域名。
- 前端**未采集**浏览器环境指纹（屏幕、时区、字体、WebGL、音频、canvas）。
