# EduCodePass 客户端安全评估

EduCodePass 是东北大学「码途」编程练习的 macOS 客户端。本仓库记录对它的安全评估。

评估对象为 1.3.0 版本。共记录 16 个问题，其中严重 2 个。

## 主要发现

两个严重问题都和私钥有关。

第一个是工厂私钥内嵌在二进制里。这个问题在 1.3.0 已经修了。

第二个是设备私钥。客户端把它存在登录钥匙串，没有设访问控制。一条命令就能读出来：

```bash
security find-generic-password -a device-key \
  -s cn.edu.neusoft.codepass.client.device_key -w
```

读出来的是 P-256 私钥，能派生对应公钥。拿到私钥就能伪造这台设备的请求签名。

其余问题按级别列出：

| 级别 | 数量 | 说明 |
|---|---|---|
| 严重 | 2 | 工厂私钥（已修）、设备私钥 |
| 高危 | 2 | 二进制完整性、证书 pinning |
| 中危 | 5 | 进程黑名单、DYLD 检测、截屏监考、焦点检测、环境位掩码 |
| 低危和信息 | 7 | 配置劫持、设备指纹、虚拟化检测等 |

## 修复建议

按优先级排：

1. 加客户端二进制完整性自校验。这是本地防护的前提。二进制可改，其他检测都能被消音。
2. 截屏改用 ScreenCaptureKit。现在调外部命令，监控进程名就能绕过。
3. 进程扫描改用 libproc。现在依赖 `/bin/ps`，改一个字符串就失效。
4. 在 macOS 实现证书 pinning。客户端日志里写了这个还没做。

设备私钥那条要单独处理。建议改用 Secure Enclave 生成不可导出的密钥，签名在硬件里完成。

## 防护做得对的地方

请求签名机制扎实。`bodyHashHex` 绑定请求体哈希，服务端重算比对。改 body 必被发现。

minisign 更新校验、Tauri IPC 鉴权、进程黑名单的本地兜底，都正常工作。
